# 3 ЗАДАНИЕ

## Структура

```
compose.yaml        БД + adminer + приложение
db/Dockerfile       образ PostgreSQL с русской локалью
sql/01_schema.sql   создание таблиц
sql/02_data.sql     демонстрационные данные
sql/03_user.sql     пользователь app_user и его права
app/app.py          программа (на основе app.py из 1 задания)
app/config.json     адрес БД (host = db — имя сервиса в compose)
app/Dockerfile      образ приложения
app/.env            переменная LOG_FILE — путь к файлу логов
```

## Предметная область: интернет-магазин

```
customers 1 ──< orders 1 ──< order_items >── 1 products
```

| Таблица       | Что хранит        | Связи                                     |
| ------------- | ----------------- | ----------------------------------------- |
| `customers`   | покупатели        |                                           |
| `products`    | товары            |                                           |
| `orders`      | заказы            | `customer_id` → `customers.id`            |
| `order_items` | позиции в заказе  | `order_id` → `orders.id`, `product_id` → `products.id` |

## Запуск

```bash
# 1. Собрать тегированный образ приложения
docker build -t rzps-app:1.0 ./app

# 2. Запустить БД и adminer
docker compose up -d db adminer

# 3. Запустить приложение в интерактивном режиме (в той же сети, что и БД)
docker compose run --rm app
```

Логин: `app_user`, пароль: `AppPassword123`.

SQL-скрипты из папки `sql` выполняются автоматически **только при первом запуске**, пока БД пустая.
Чтобы пересоздать БД с нуля: `docker compose down -v`, затем снова шаг 2.

Логи дублируются в файл `logs/app.log` (на компьютере, рядом с compose.yaml).

## Пункты меню ↔ пункты задания

| Меню | Пункт задания | Что делает                                                  |
| ---- | ------------- | ----------------------------------------------------------- |
| 1    | 6.1           | `SELECT * FROM table`                                       |
| 2    | 6.1           | `SELECT ... WHERE колонка = значение`                        |
| 3    | 6.1           | `SELECT ... WHERE кол1 = знач1 AND кол2 = знач2`             |
| 4    | 6.2           | `UPDATE ... SET кол1 = ..., кол2 = ... WHERE id = ...`       |
| 5    | 6.2           | `UPDATE ... SET кол = ... WHERE кол IN (знач1, знач2, ...)`  |
| 6    | 6.3           | `INSERT` одной строки                                       |
| 7    | 6.3           | заказ в `orders` + товар в `order_items` (id через `RETURNING`) |
| 8    | 6.4           | несколько строк в одну таблицу                              |
| 9    | 6.4           | несколько заказов, в каждом несколько товаров               |

Примеры для демонстрации:
- меню 2 → `products` → `category` → `Электроника`
- меню 3 → `orders` → `2,4` → customer_id `1`, status `оплачен`
- меню 5 → `orders` → `status` → `отменён` → по `id` → `4,5`
- меню 7 → покупатель `1`, товар `3`, количество `2`, цена `5000`
- ошибка: меню 7 → покупатель `999` → «Ссылка на несуществующую запись»

## Как это работает (на вопросы преподавателя)

**Защита от SQL-инъекций.**
- Значения передаются только через плейсхолдеры `%s` — psycopg отправляет их в БД отдельно от текста запроса, поэтому они никогда не становятся частью SQL-кода.
- Названия таблиц и колонок нельзя передать через `%s`. Поэтому пользователь выбирает их **по номеру из списка** `TABLES` (белый список), а в запрос они вставляются через `sql.Identifier(...)`, который оборачивает имя в кавычки.
- Для `IN (...)` на каждое значение создаётся свой плейсхолдер: `IN (%s, %s, %s)`.

**Транзакции.** Каждый пункт меню — одна транзакция: при успехе `commit()`, при ошибке `rollback()`.
Если в меню 7/9 заказ создался, а товар указан неверно — заказ тоже отменяется.
(id из последовательности при этом «сгорает», поэтому в нумерации могут быть пропуски — это нормально.)

**Логи.**
- Успех → `stdout` (`[OK] ...`), ошибка → `stderr` (`[ОШИБКА] ...`), пользователю показывается понятный текст.
- Если задана переменная окружения `LOG_FILE`, те же записи дублируются в файл, а для ошибок — вместе с настоящим текстом ошибки от БД.

**Права `app_user`.** Только `SELECT`, `INSERT`, `UPDATE` на таблицы и `USAGE` на последовательности (для `SERIAL`).
Удалять строки и менять структуру таблиц не может.
